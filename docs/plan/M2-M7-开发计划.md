### 2.2 技术选型与实现要点

- **状态管理**：`EmotionState` / `PAD` / `EmotionSnapshot` 全部 frozen；引擎只做编排，计算下沉纯函数。
- **时钟注入**：`clock: Callable[[], float]`；`advance(seconds)` 不 sleep；`emotion/` 禁止直接 `time.time()`（`ruff` 白名单 + 单测 lint 断言）。
- **持久化**：S3 用 `JsonEmotionRepo`（原子写、历史环形缓冲）；S6 替换为 SQLite 实现，接口不变。
- **刺激裁决**：词典 Level 1 → 人格调制 → 软饱和 → 标签推导 → 状态机；LLM hint 只做增量与建议，引擎拥有否决权。
- **表现**：`map_snapshot()` 输出 `PresentationCue`（motion / expression / tts / params），权重 `0.4 + 0.6×intensity`。
- **调试**：调试 API 与 DevPanel 同源；面板只读 `emotion.update` + 历史接口，不自行插值。
- **主动性**：独立 `ProactiveController`，1h ≤3 次、间隔 ≥10min、quiet_hours 静默、滑杆 0 关闭；文案取角色卡 `proactive_lines`。

### 2.3 验收与测试策略

- 七个原语单测；状态机三条约束；同刺激两人格不同标签；共情反转；不应期；habituation 1:0.7:0.49；`advance(8h)` 重逢；离线恢复；tick 抖动。
- API 用 `TestClient`；编排用 `MockLLMProvider`；覆盖率门禁 `--cov=app.emotion --cov-fail-under=80`。
- 演示脚本即路线图 3.2 的 M3 七条。

### 2.4 依赖与并行

- T3-A/B/C/D 串行（同一状态与契约）；T3-E（前端）可在 T3-C 契约冻结后并行；T3-F 随模块推进同步写；T3-H 可与 T3-D 并行。

## 3. S4 语音链路（P1）

### 3.1 任务分解（按优先级）

| 优先级 | 任务 | 内容 | 依赖 |
| --- | --- | --- | --- |
| P0 | T4-A 协议与 Provider | `voice/asr/base.py`、`voice/tts/base.py`；音频 WS 消息：`audio.in_*`、`asr.*`、`audio.out_*`、`audio.stop` | T3-C |
| P0 | T4-B ASR | faster-whisper（int8/small，`initial_prompt`）；能量 VAD（可选 silero）；`asr.partial/final/error` | T4-A |
| P0 | T4-C TTS | edge-tts（rate/pitch/volume）；文本清洗；40 字切句；首句优先 + 并发预取 | T4-A |
| P0 | T4-D 前端录音/播放 | `Recorder`（16kHz mono、push-to-talk/always-on）、`Player`（按 `start(when)` 无缝）、`HalfDuplex` 五态机 | T4-A |
| P0 | T4-E 打断全链路 | 6 环节取消：WS → turn_registry → LLM → TTS → 播放队列 → 恢复收音；0.3s 静音 | T4-B/C/D |
| P0 | T4-F 口型联动 | 真实 TTS 音频 → `AnalyserNode` → `LipSync`；30s 无漂移 | T4-D |
| P1 | T4-G 音频情绪 | RMS / 语速修正刺激 magnitude（≥20% 差异） | T4-B、T3 |
| P1 | T4-H 双模式与设置 | 半双工开关、设备枚举、语音选择、试听 | T4-D、S5 设置面板 |

### 3.2 技术选型与实现要点

- **ASR**：`faster-whisper`（CTranslate2，CPU int8）；默认 `small`，测试/低配回落 `tiny`；模型惰性加载，缺失时 `sys.error{ASR_UNAVAILABLE}` 并保留文字输入。
- **TTS**：`edge-tts` 流式 MP3；`pitch` 百分比、`rate` 倍率映射；失败 >3 次/分钟自动关闭语音输出。
- **音频传输**：WS 二进制/Base64（JSON 信封统一走 Base64，避免协议分叉）；16kHz PCM 上行，MP3 下行；20–40ms 帧。
- **半双工**：`IDLE→LISTENING→THINKING→SPEAKING→INTERRUPTED` 显式状态机，非法转移日志。
- **VAD**：首版能量阈值 + 700ms 静音端点；保留 silero 接口。
- **口型**：沿用 S2 振幅法，不做假音频。

### 3.3 验收与测试策略

- ASR/TTS 用 Fake Provider 单测 + 本机真实 edge-tts 冒烟（短句）；ASR 真实模型用 `tiny` 冒烟，记录识别文本。
- 五态机合法/非法转移各 3 例；打断单测断言 6 环节全部释放；前端构建通过；首音延迟 P50 记录。
- 演示：按住说→实时字幕→语音回复→口型→点击打断。

### 3.4 依赖与并行

- T4-A 先行冻结协议；T4-B 与 T4-C 可并行（不同目录）；T4-D 依赖协议；T4-E 最后集成。

## 7. 质量门禁与提交节奏

每个阶段收工必须全部通过：

```powershell
powershell -File scripts/gate.ps1 -Stage S3   # ruff + mypy + pytest + coverage
npm.cmd --prefix frontend run build            # tsc + vite
python scripts/export_schema.py && node scripts/gen-types.mjs
git diff --exit-code -- shared frontend/src/types
```

- 修复 `gate.ps1` 的前端路径（`frontend` 而非 `../frontend`），确保本地与 CI 一致。
- 每阶段：更新 README/路线图进度与证据 → `git add` 明确文件 → 提交 `S<n>: …` → `git push -u origin forks12`。
- 每阶段末生成 `docs/evidence/s<n>-*.txt`（测试/覆盖率/冒烟输出），不做无证据的勾选。
